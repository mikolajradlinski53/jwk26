# Push i ogłoszenia — plan implementacji

**Goal:** Powiadomienia push: ogłoszenia admina (wszyscy / drużyna / pula) i automaty
(przyjęcie zgłoszenia, zaliczone pole bingo).

**Architecture:** Outbox `powiadomienia` (kanał `push`). Wyzwalacz przez `pg_net`
woła `/api/push` z sekretem; trasa pobiera paczkę `pobierz_push` (subskrypcje
adresatów, licznik prób ≤ 5), wysyła `web-push`, oznacza `oznacz_push` i kasuje
martwe endpointy (404/410). `pg_cron` co minutę ponawia zaległe. Trasa ma tylko
klucz anon + sekret (jak arkusz). Automaty to wyzwalacze na `registrations`
i `bingo_submissions`, bez zmian w funkcjach akceptacji.

**Spec:** `docs/superpowers/specs/2026-09-28-mapa-mechanizmow-design.md` §3 „11".

## Wdrożenie (kolejność ma znaczenie)

1. Migracja na produkcję — `push_url` zostaje pusty, więc nic jeszcze nie wysyła.
2. Vercel → Environment Variables: `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`
   (z `.env.local`), `PUSH_SEKRET` (`select wartosc from sekrety where klucz = 'push'`
   na produkcji). Redeploy.
3. Dopiero potem `update sekrety set wartosc = 'https://jwk26.pl/api/push' where klucz = 'push_url';`
   Wcześniej trasa odpowiadałaby 503 i powiadomienia zużyłyby swoje pięć prób.
4. Test na telefonie: włącz w „Więcej", wyślij ogłoszenie do siebie (drużyna).
