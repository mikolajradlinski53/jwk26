# Preludium — plan wdrożenia

> **Dla pracujących agentowo:** WYMAGANY PODSKILL: użyj
> superpowers:subagent-driven-development (zalecane) albo
> superpowers:executing-plans, żeby wykonać ten plan task po tasku.
> Kroki mają pola wyboru (`- [ ]`) do odhaczania.

**Cel:** Zamienić logowanie mailem na logowanie Google Workspace i postawić
przed apką publiczny landing z twardym zamkiem instalacji.

**Architektura:** Apka przenosi się pod prefiks `/app`, dzięki czemu bramka
w `proxy.ts` chroni jeden prefiks zamiast listy wyjątków. Landing i ekran
wejścia zostają publiczne. Zamek instalacji rozstrzyga CSS (`display-mode`),
nie JavaScript, więc nie ma błysku niewłaściwej treści przed hydracją.
Bramka domenowa zostaje bez zmian — wyzwalacz `enforce_email_domain`
na `auth.users` odpala się niezależnie od dostawcy tożsamości.

**Stos:** Next.js 16 (App Router), Supabase (Auth + Postgres), Tailwind CSS v4,
Vitest przeciw osobnemu projektowi testowemu.

**Spec:** `docs/superpowers/specs/2026-09-17-preludium-design.md`

---

## Jak czytać ten plan

Taski 1 i 3 wymagają **właściciela projektu przy klawiaturze** — konfiguracji
w konsolach Google i Supabase nie da się zrobić z repozytorium, a sprawdzenia
na iPhonie nie da się zrobić w ogóle bez iPhone'a. Reszta jest do wykonania
samodzielnie.

Kolejność nie jest przypadkowa: **logowanie ląduje na produkcji jako trzeci
task**, przed przenosinami tras i przed landingiem. Powód jest jeden — jedyne
nieusuwalne ryzyko tego projektu (czy logowanie Google wraca poprawnie do apki
przypiętej na iPhonie) musi zostać rozstrzygnięte, zanim cokolwiek na nim
stanie. Gdyby okazało się zepsute, zmienia się kształt zamka instalacji, a to
połowa planu.

**Taski 7 (komponent licznika), 8 i 9 opisują intencję i ograniczenia zamiast
przepisywać kod.** To celowe: warstwę graficzną landinga — układ, motyw
jesienny, rysunek żaby — robi właściciel projektu, więc dyktowanie dokładnego
JSX byłoby pisaniem czegoś, co i tak zostanie przerysowane. Te taski podają za
to twarde wymagania (co musi być widoczne w pierwszej klatce, co musi ustąpić
przy `prefers-reduced-motion`, jakie dane wchodzą), bo te przetrwają każdą
zmianę wyglądu. Wszystko, co dotyka bramki, logowania, zamka i danych, ma
w planie pełny kod.

- [ ] **Krok 1: Tłumaczenie błędów logowania**

`src/lib/auth/blad.ts`:

```ts
/**
 * Zamienia błąd logowania na zdanie, z którym człowiek ma co zrobić.
 *
 * Najważniejszy przypadek to obca domena. Wyzwalacz `enforce_email_domain`
 * rzuca wyjątek w trakcie tworzenia konta, a GoTrue opakowuje to we własny,
 * ogólny komunikat — dlatego dopasowujemy oba warianty: naszą treść i tę,
 * którą podstawia Supabase.
 */
export function bladLogowania(surowy: string): string {
  if (/Dozwolone wy|Database error saving new user|unexpected_failure/i.test(surowy)) {
    return "Ten adres nie należy do Samorządu. Zaloguj się kontem @samorzad.ue.wroc.pl.";
  }
  if (/access_denied|cancelled|consent_required/i.test(surowy)) {
    return "Logowanie zostało przerwane.";
  }
  if (/expired|invalid.*(code|grant)/i.test(surowy)) {
    return "Ta próba logowania wygasła. Spróbuj jeszcze raz.";
  }
  return "Logowanie się nie udało. Spróbuj jeszcze raz.";
}
```

- [ ] **Krok 2: Trasa powrotu**

`src/app/auth/callback/route.ts`:

```ts
import { NextResponse, type NextRequest } from "next/server";
import { createClient } from "@/lib/supabase/server";
import { bladLogowania } from "@/lib/auth/blad";

export async function GET(request: NextRequest) {
  const { searchParams, origin } = request.nextUrl;

  function zBledem(surowy: string) {
    const url = new URL("/login", origin);
    url.searchParams.set("blad", bladLogowania(surowy));
    return NextResponse.redirect(url);
  }

  // Google potrafi wrócić z błędem zamiast kodu — wtedy `code` nie ma wcale.
  const odmowa = searchParams.get("error_description") ?? searchParams.get("error");
  if (odmowa) return zBledem(odmowa);

  const code = searchParams.get("code");
  if (!code) return zBledem("brak kodu");

  const supabase = await createClient();
  const { error } = await supabase.auth.exchangeCodeForSession(code);
  if (error) return zBledem(error.message);

  // Dokąd dalej, rozstrzyga bramka na podstawie statusu profilu.
  return NextResponse.redirect(new URL("/", origin));
}
```

`tests/bramka.test.ts`:

```ts
import { describe, it, expect } from "vitest";
import { readdirSync } from "node:fs";
import { join, resolve } from "node:path";

const KORZEN = resolve(__dirname, "../src/app");

// Trasy, które mają być publiczne świadomie. Każda inna musi siedzieć
// pod /app, bo tylko ten prefiks obejmuje bramka w proxy.ts.
const PUBLICZNE = new Set(["/", "/regulamin", "/wejscie"]);

/** Zbiera adresy wszystkich stron z systemu plików. */
function trasy(katalog: string, prefiks = ""): string[] {
  const znalezione: string[] = [];
  for (const wpis of readdirSync(katalog, { withFileTypes: true })) {
    if (wpis.isDirectory()) {
      // Grupy tras `(nazwa)` nie tworzą segmentu adresu.
      const segment = wpis.name.startsWith("(") ? "" : `/${wpis.name}`;
      znalezione.push(...trasy(join(katalog, wpis.name), prefiks + segment));
    } else if (wpis.name === "page.tsx") {
      znalezione.push(prefiks === "" ? "/" : prefiks);
    }
  }
```

```ts
/**
 * Rozpoznanie systemu i przeglądarki po stronie klienta.
 *
 * Wyłącznie do doboru instrukcji — nie do decydowania o dostępie. Ciąg
 * identyfikacyjny przeglądarki da się podrobić, więc żadne zabezpieczenie

export type System = "ios" | "android" | "inny";

export function system(): System {
  if (typeof navigator === "undefined") return "inny";
  const ua = navigator.userAgent;
  if (/iPad|iPhone|iPod/.test(ua)) return "ios";
```

`src/lib/odliczanie.ts`:

```ts
export type Odliczanie = {
  minelo: boolean;
  dni: number;
  godziny: number;
  minuty: number;
  sekundy: number;
};

const MINIONE: Odliczanie = {
  minelo: true, dni: 0, godziny: 0, minuty: 0, sekundy: 0,
};

/**
 * Ile zostało do `docelowa`.
 *
 * Data docelowa jest zapisana z przesunięciem strefy (`+02:00`), więc wynik
 * nie zależy od tego, jak ustawiony jest telefon uczestnika — a bywa ustawiony
 * dziwnie. Po terminie zwracamy stan miniony zamiast wartości ujemnych:
 * świeżaki przyjmowane są tydzień przed wyjazdem, więc jeden licznik wygaśnie,
 * gdy drugi jeszcze chodzi, i ten przypadek zdarzy się na pewno.
 */
export function odliczanie(docelowa: string | null, teraz: Date): Odliczanie {
  if (!docelowa) return MINIONE;

  const cel = new Date(docelowa).getTime();
  if (Number.isNaN(cel)) return MINIONE;

  const roznica = cel - teraz.getTime();
  if (roznica <= 0) return MINIONE;

  const sekundyRazem = Math.floor(roznica / 1000);
  return {
    minelo: false,
    dni: Math.floor(sekundyRazem / 86400),
    godziny: Math.floor((sekundyRazem % 86400) / 3600),
    minuty: Math.floor((sekundyRazem % 3600) / 60),
    sekundy: sekundyRazem % 60,
  };
}
```

- [ ] **Krok 1: Liście**

`src/app/landing/Liscie.tsx` — klient rysujący na `<canvas>` w warstwie
`fixed inset-0 -z-10` z `aria-hidden="true"` i `pointer-events-none`.

Trzy rzeczy, bez których to jest usterka, nie dekoracja:

1. **`prefers-reduced-motion`** — sprawdzane przez
   `window.matchMedia("(prefers-reduced-motion: reduce)")`. Reguła globalna
   w `globals.css` wyłącza animacje CSS, ale kanwy nie dotyczy.
2. **`visibilitychange`** — pętla zatrzymuje się, gdy karta jest niewidoczna.
3. **Mniej liści na słabszym sprzęcie** — przy
   `navigator.hardwareConcurrency <= 4` liczba liści spada z 40 do 15.

Pętla chodzi na `requestAnimationFrame`, a identyfikator klatki jest sprzątany
w funkcji zwracanej z `useEffect`.
